Les 6 domaines en un seul processus

Schéma

On prépare les données et les invites, on construit et orchestre l’agent, on le teste et le déploie. En production, chaque requête suit le trajet en bleu ; ses traces alimentent l’observation, qui renvoie vers une nouvelle version de l’agent. Le détail de chaque phase suit le schéma.

1Préparer les données Data 360 Fundamentals · 20 %

  • Le Data Library automatise la chaîne : ingestion, découpage, vectorisation, index de recherche et retriever par défaut.
  • Le contenu non structuré arrive dans un UDLO, est mappé vers un UDMO, puis découpé et indexé.
  • Chunks trop petits : contexte perdu. Trop grands : bruit, coût et réponses diluées.
  • Vectoriel = proximité de sens. Mot-clé = termes exacts (codes, références). Hybride = les deux.
  • Retriever individuel : un index, des filtres, un nombre de résultats. Ensemble : combine plusieurs retrievers. Ils se gèrent dans Einstein Studio.

2Concevoir les invites Prompt Engineering · 20 %

  • Field Generation remplit un champ depuis la page (Dynamic Forms). Sales Email sert le compositeur d’e-mails. Flex accepte jusqu’à 5 entrées et s’appelle depuis Flow, Apex ou un agent.
  • Ancrage, du plus simple au plus puissant : champs de fusion, listes associées, flux Template-Triggered Prompt Flow, Apex @InvocableMethod, retriever.
  • Cycle : aperçu (invite résolue et réponse) → enregistrer une version → activer. Une seule version est active.
  • Prompt Template Manager crée et gère, Prompt Template User exécute. L’ancrage respecte les permissions de l’utilisateur.
  • Model Builder liste les modèles standards et BYOLLM ; chaque modèle d’invite précise le sien.

3Construire l’agent AI Agents · 35 %

  • Employee pour les utilisateurs internes, Service pour les clients externes.
  • Agent Script : start_agent classe la demande et la route vers un subagent (ex-topic).
  • -> ouvre la logique déterministe (if, run, set, transition to) ; | ouvre les instructions envoyées au LLM.
  • Variables mutable ou linked ; filtres et available when conditionnent l’accès à une action.
  • Des descriptions de classification distinctes évitent le mauvais routage.
  • Actions : Flow, Apex invocable, modèle d’invite, Answer Questions with Knowledge. Confirmation utilisateur pour les actions sensibles.

4Orchestrer Multi-Agent Orchestration · 5 %

  • Le multi-agents se justifie quand le périmètre couvre des domaines distincts (équipes, sécurité, outils) qu’un seul agent route mal.
  • Il coûte en latence, en appels de modèle et en complexité de test.
  • L’orchestrateur route vers des sous-agents spécialisés et consolide la réponse.
  • MCP relie un agent à des outils et des données. A2A relie des agents entre eux ; ils se découvrent par leur Agent Card.

5Tester et déployer Testing, Deployment & Maintenance · 10 %

  • Testing Center lance des tests en lot, importés en CSV ou générés par IA.
  • Chaque test vérifie la rubrique, les actions et la réponse attendues ; un LLM juge la réponse sur le fond.
  • En sandbox : les actions s’exécutent vraiment pendant les tests.
  • Déployer l’agent avec ses dépendances, vérifier l’Agent User en production, déplacer Data 360 par Data Kits. Un modèle d’invite se déploie en GenAiPromptTemplate.
  • On fait évoluer un agent actif par une nouvelle version, activée après les tests.

6Exécuter une requête AI Agents · 35 %

  • Messagerie web : Enhanced Chat et un flux Omni-Channel. L’escalade vers un humain passe par une route sortante Omni-Channel.
  • Agent API pour une app ou un site avec sa propre interface, via OAuth client credentials.
  • Un agent Employee s’exécute comme l’utilisateur connecté ; un agent Service comme son Agent User (moindre privilège).
  • Atlas classe, planifie, exécute une action, évalue le résultat et reboucle si besoin.
  • Le Trust Layer protège l’aller (récupération sécurisée, masquage, défense d’invite) et le retour (démasquage, toxicité, audit). Le fournisseur du LLM ne conserve rien.

7Observer et améliorer Governance & Observability · 10 %

  • Piste d’audit, feedback et traces de session sont stockés dans Data 360.
  • Agentforce Command Center donne la vue d’ensemble : santé, adoption, performance.
  • Analytique : résolution, escalade, satisfaction. Optimisation : regrouper les demandes et repérer les échecs.
  • Boucle : analyser les traces → corriger instructions ou données → re-tester → activer une nouvelle version.
